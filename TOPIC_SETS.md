## What changed and why

Previously each topic had exactly ONE matched question (across Set A/B). That's too
thin to measure learning gain reliably. Now **each topic has its own 5-question
pretest and a parallel 5-question posttest** (same 5 sub-concepts, reworded scenarios,
different surface wording, options reordered). There is no more Set A / Set B split —
a participant's assigned topic (from the roster) determines which single question set
they see for both pre-test and post-test.

**Scoring:** 1 point per correct answer, pretest and posttest each out of 5.
`learning_gain = post_score − pre_score` (range −5 to +5).

**No overlap with planted errors:** none of these questions test the specific claims
planted during the chat session (TOPICS.md section 3), so the post-test measures
general learning from the topic, not just whether they caught the planted error.

## Content structure for implementation

Store as JSON, one file per topic (or one combined file), shape:

```json
{
  "topicId": "procrastination",
  "pretest": [
    { "itemId": "procrastination_pre_1", "concept": "cause", "question": "...", "options": ["...","...","...","..."], "correctIndex": 1 }
  ],
  "posttest": [
    { "itemId": "procrastination_post_1", "concept": "cause", "question": "...", "options": ["...","...","...","..."], "correctIndex": 0 }
  ]
}
```

`concept` must match between pretest item N and posttest item N for the same topic
(they are the parallel-form pair). `correctIndex` is 0-based (A=0, B=1, C=2, D=3).
